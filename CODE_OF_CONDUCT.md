# Code of conduct

## Our standard

We want Horme Flow to be a respectful, practical, and welcoming open-source project. Be considerate, critique ideas and code rather than people, respect privacy, and assume contributors have different levels of experience, language fluency, and access needs.

Unacceptable behavior includes harassment, discrimination, threats, sexualized attention, deliberate intimidation, publishing someone else's private information, or repeatedly disrupting project work.

## Privacy-specific expectations

Do not post another person's voice, transcript, private code, credentials, contact details, or workplace content. Use synthetic examples in issues and tests. Remove personal information from logs and screenshots before sharing them.

## Enforcement

Maintainers may edit or remove content, close contributions, or temporarily or permanently restrict participation when behavior threatens people or the project. Enforcement decisions should be documented privately and applied consistently.

Before public beta, the maintainers must publish a private contact address for conduct reports. Until then, avoid disclosing sensitive details in a public issue.
